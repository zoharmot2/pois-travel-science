# v1.4 Stage 9 — Multi-Geometry Search and Detail Panel

Stage 9 refines search and entity inspection now that the website renders points, lines, and polygons together.

## Search scope

Search operates on the entities currently rendered after the active **POI Type** and **Geometry** filters. Hidden entities are not returned until their filter state is restored.

Search remains name-based (`POI_Name`) and does not alter ArcGIS data.

## Search results

Typing in the Search field is debounced by 180 ms. Up to eight ranked matches are shown:

1. exact name match;
2. names beginning with the query;
3. names containing the query.

Each result shows the entity name, geometry family, POI Type, and Research Topic when present. Search supports mouse/touch selection and keyboard navigation with Up/Down, Enter, and Escape.

Selecting a result:

- focuses a Point using a point zoom;
- fits the bounds of a Line or Polygon;
- opens the shared Entity Detail Panel.

## Detail Panel

The same Detail Panel is used for every geometry family. It displays common ArcGIS attributes and geometry-aware location information:

- Point: actual coordinates;
- Line/Polygon: derived map center and extent;
- Geometry family and original GeoJSON geometry type;
- source dataset (`points`, `lines`, or `polygons`);
- stable GlobalID-based Entity ID.

Blank `POI_Type` or `POI_Topic` values are displayed as **Unspecified** in the UI only. Source data is not modified.

## Attachments

Stage 10 replaces extension-only presentation with structured attachment metadata generated by the ArcGIS export. The Detail Panel groups media into **Photos**, **Audio**, and **Other Attachments**:

- images render as thumbnails;
- downloaded audio renders with an HTML5 audio player plus an Open audio file link;
- video remains a direct ArcGIS link;
- other unsupported media remains an explicit attachment link.

The Entity model retains a compatibility fallback for older snapshots that contain only the legacy `attachments` URL/path array.

## Performance and safety

Search scans only the currently rendered Leaflet layers and returns a maximum of eight suggestions. It does not create additional network requests. Result labels are written with DOM `textContent`; source strings are not injected as HTML.
