# v1.5.0 Nominatim-only — operational closeout checklist

**Status: release candidate until local/production checks are complete.**

## Limits and scope
- Only Nominatim reverse administrative enrichment; no Overpass entity matching.
- Authoritative AGOL/Field Maps data stays unchanged.
- 3 non-point geometries are excluded from reverse geocoding by design; `eligible_points` counts only valid Points.
- English names requested; local names remain a fallback.
- Source-specific notes and provenance accompany completed records.

## Safe installation
1. Back up working project and `data/derived/enrichment.json`.
2. Apply this patch at the repository root. The ZIP contains no replacement enrichment data.
3. Test: `py scripts/test_enrichment.py`, `py scripts/enrich_data.py --offline`, `py scripts/qa_enrichment.py`.
4. Configure repository Actions secret `ENRICHMENT_USER_AGENT` using a meaningful contactable identifier; do not commit personal contact information in code.
5. The weekly workflow will now enrich at most **10** new/changed records per run at **16 seconds apart**. If the secret is absent, it performs an offline cache-only update.
6. Inspect `data/derived/enrichment-report.json` and workflow artifacts. Inspect `updated_this_run` and `errors_this_run`.

## Full initial backfill
The OSM Foundation public Nominatim service discourages regular bulk processing. Its bulk policy requires a single thread, one machine, cached results, and a maximum of 4 requests/minute for long-running or periodic tasks. See https://operations.osmfoundation.org/policies/nominatim/ . **Do not attempt a 1,200-request weekly public-API batch.**

For the initial backfill, prefer an approved/self-hosted or third-party Nominatim provider with a suitable quota. The code currently targets the public endpoint; switching providers requires separately configuring the endpoint. With public Nominatim, use only small policy-compliant batches (e.g. `py scripts/enrich_data.py --max-requests 10`); completed records are reused. Large-scale one-time bulk use needs checking suitability and provider capacity first.

## Release gate
- `py scripts/qa_enrichment.py` succeeds.
- `py scripts/test_release_readiness.py` succeeds (all valid Point geometries enriched).
- Inspect English fallback, field-level accuracy and attribution in sample POIs.
- Run website locally and check standalone/embed display, search, maps and details.
- Run GitHub Actions workflow once; confirm reports, commits and deployed pages.
- Only then commit, tag and release `v1.5.0` using GitHub Desktop on main.
